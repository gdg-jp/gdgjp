# Meet architecture

`apps/meet` is a feature-first React Router v7 SSR application on Cloudflare Workers (`meet.gdgs.jp`).

## Directory structure and ownership

| Responsibility | Path |
| --- | --- |
| Relying-party sessions, sign-in redirects, chapter claims, and access guards (`requireUser`, `requireUserWithChapter`, `requireAdmin`) | `app/features/auth/` |
| Chapter directory (`ACCOUNTS` HTTP) and active chapter-member lookup (`ACCOUNTS_DIRECTORY` RPC; member emails stay server-only) | `app/features/directory/` |
| Shared Google host OAuth connection, AES-GCM token encryption, access-token caching/refresh, email normalization, and Google API clients (Meet, Calendar, Drive, Workspace Events) | `app/features/google/` |
| Meeting creation (Strategy B: Meet space → Calendar event → async member sync), editing, chapter resync, cancellation, `cleanup_meeting`, invitee resolution, view/edit access, D1 repository, artifact reshare enqueueing, and UI forms/lists | `app/features/meetings/` |
| Workspace Events Pub/Sub Push JWT verification (WebCrypto + Google JWKS), Push envelope handling (`processed_events` dedupe + rollback), Workspace Events subscription lifecycle (`google_subscription`), and admin subscription status widget | `app/features/events/` |
| Meeting artifacts (`conference_records`, `artifacts` repository), `process_artifact` (Meet API fetch + chat-log detection), `share_artifact` (Drive reader sharing + Calendar attachment), and UI lists (`ArtifactList`, `FailedArtifactsCard`) | `app/features/artifacts/` |
| Hourly cron orchestration (subscription maintenance, 7-day active meeting backfill, pending artifact requeue) | `app/features/cron/` |
| `MEET_JOBS` Queue message types and handler registry (`sync_members`, `cleanup_meeting`, `process_artifact`, `share_artifact`) | `app/features/jobs/` |
| Shared signed-in application shell (`AppLayout`) | `app/layouts/AppLayout.tsx` |
| Domain-independent primitives (`useHydrated`) | `app/lib/` |
| Route modules owning loaders, actions, metadata, and composed screens | `app/routes/` (`meetings/home.tsx`, `meetings/new.tsx`, `meetings/detail.tsx`, `meetings/edit.tsx`, `admin/google.tsx`, `admin/google.callback.ts`, `api.google.events.ts`, `dev.simulate-event.ts`, `auth/no-chapter.tsx`, auth plumbing) |
| Route registration | `app/routes.ts` |
| Cloudflare Worker entrypoint (`fetch` + `queue` + `scheduled`) | `workers/app.ts` |
| D1 migrations (`schema.sql` is generated by `migrate:local`) | `migrations/` |
| Architecture guardrails | `tests/architecture/` |

## Dependency rules

- `app/features/` never imports `app/routes/`.
- `app/lib/` and `app/components/` never import `app/features/` or `app/routes/`.
- Client TSX modules under `app/components/`, `app/features/`, and `app/layouts/` import `*.server` modules only as types (`import type`).
- Route modules never call `.prepare(` directly; D1 queries live in feature repositories.
- Source files under `app/` and `workers/` stay at or under 400 lines.
- Unit tests sit beside the module they cover (`*.test.ts` / `*.test.tsx`).

## Architecture tests

`tests/architecture/` enforces the rules above as part of `pnpm --filter @gdgjp/meet test`:

- `layering.test.ts` — checks import direction, `.server` boundaries, and SQL ownership.
- `file-size.test.ts` — enforces the 400-line ceiling.
- `test-colocation.test.ts` — ensures every unit test under `app/` has an adjacent subject module.
- `route-urls.test.ts` — snapshots the public route table in `app/routes.ts` so URL additions are intentional.

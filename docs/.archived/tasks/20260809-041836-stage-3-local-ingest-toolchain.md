## Acceptance criteria

### 1. Deterministic constraint

The push implementation in `cli/internal/wiki/remote_helper.go` rejects changes outside `pages/` with:

```
only pages/** may be pushed (changed ...)
```

Therefore **`raw/` must not be Git-tracked in the clone**.

`gdg wiki clone` writes the following to `.gitignore`; hydrate raw content with a separate command.

```
raw/
AGENTS.md
INGEST_QUEUE.md
.gdgwiki/
```

This is a design premise. Do not refactor it by suggesting that `raw/` could be tracked as well. State it as a prohibition in `AGENTS.md` too.

### 2. Clone layout

```
<clone>/
  .git/
  .gitignore          ← generated by gdg wiki clone
  AGENTS.md           ← served by the server; agent instructions
  INGEST_QUEUE.md     ← generated by gdg wiki ingest
  pages/**            ← origin: agent only; Git-tracked and synced on push
  raw/**              ← not Git-tracked; sources plus origin: human pages
  .gdgwiki/
    config.json       ← clone settings such as lang
    state.json        ← local record of ingested hashes
```

### 3. Single-language clones (breaking change)

There are almost no English users of `gdgs.jp`, and Worker-side AI translation is sufficient. Having agents write two languages wastes tokens, so clones become single-language.

- `gdg wiki clone --lang ja` (default `ja`) fetches only the selected language.
- Consolidate filenames from `ja.md` / `en.md` to **`page.md`**. The front matter `language` carries the language.
- Store `lang` in `.gdgwiki/config.json`, read by the remote helper.
- Add `GET /api/cli/wiki/snapshot?lang=ja`, returning only the specified locale.

**Change sync to partial-locale updates.** Current `api.cli.wiki.sync.ts` always overwrites both locales via `UPDATE pages SET ... title_en=?, content_en=? ...`; a Japanese-only push would erase every English page. This is the largest risk in this stage.

- Make `ja` / `en` optional in the sync page schema; UPDATE **only locales that are present**.
- Update `wiki/openapi/paths/sync.yaml` and the Go client (`cli/internal/wiki/client.go`) together.

Also **enqueue translations during sync**.

- When Japanese `content` / `title` / `summary` changes, call `env.TRANSLATION_QUEUE.send({ pageId })`.
- Do not enqueue unchanged pages (avoid needless API costs).

Existing clones (for example, `~/proj/wiki`) will not work after the format change. Require re-cloning and say so in command output.

### 4. `origin` — Route human-authored pages to raw

Add an `origin` column to `pages` (`human` | `agent`, default `human`).

**Determine origin from the creation route.**

- Created via the Wiki app editor (`wiki.new.tsx`, etc.) → `origin: human`
- Created via CLI sync → `origin: agent`

| Surface | `origin: human` | `origin: agent` |
|---|---|---|
| Wiki app | Show as a normal page | Show as a normal page, with the editor warning: “This page is managed by Ingest. Edits may be overwritten by the next ingest.” |
| Clone `pages/` | Do not emit | Emit |
| Clone `raw/` | Emit as `raw/wiki-human/<slug>.md` | Do not emit |
| Sync upsert | **Reject with server 4xx** (enforced, not merely conventional) | Allowed |

This prevents agents from structurally rewriting human prose while allowing it to be read as primary information, consistent with `llm-wiki.md`: raw is read by LLMs but never rewritten.

**Constraint:** A page with `origin: human` cannot parent a page with `origin: agent`. A missing parent from `pages/` breaks the clone hierarchy (`pageDir` in `cli/internal/wiki/local.go` fails with "missing parent"). Reject this in both the sync API and the Wiki-app parent selector.

### 5. Initialize namespaces by type

Create top-level `events/`, `venues/`, `vendors/`, `people/`, `orgs/`, and `playbooks/` pages, plus `index` / `log`, in migrations (`origin: agent`, `page_type` corresponding type / `wiki-index` / `wiki-log`).

Extend `pageType` in `wiki/shared/ingestion/domain.ts`.

- Existing: `event-report` / `speaker-profile` / `project-log` / `how-to-guide` / `onboarding-guide` / `survey-report`
- Add: `event` / `venue` / `vendor` / `person` / `organization` / `playbook` / `wiki-index` / `wiki-log`

Make `index` and `log` read-only in the Wiki app.

### 6. CLI commands

Add these to `cli/internal/command/wiki.go`.

**`gdg wiki clone --lang ja DIRECTORY`**
Add `--lang` to the existing clone and generate `.gitignore` and `.gdgwiki/config.json`.

**`gdg wiki raw pull`**
Call `GET /api/cli/wiki/sources` (a manifest with hashes) and `GET /api/cli/wiki/sources/:documentId/content`; synchronize `raw/**` and `AGENTS.md`, then persist the complete manifest in `.gdgwiki/state.json`. The manifest includes `sources` documents and `origin: human` pages. Do not download a file whose local hash matches the manifest.

**`gdg wiki ingest`**
Do not call an LLM.

1. Require a previously saved local manifest; instruct the operator to run `gdg wiki raw pull` if absent.
2. Compare the local ingested hashes with that manifest and enumerate un-ingested documents.
3. Write `INGEST_QUEUE.md` (source name, `raw/` path, change type new/changed, prior hash). The agent processes **only the first item**, so prioritize oldest first.
4. Print the coding-agent prompt to standard output without making Wiki API or Git requests.

With `--agent claude|codex`, pass the prompt and shell out to the agent.

**`gdg wiki ingest --commit`**
Update `.gdgwiki/state.json` with ingested hashes. The completion record is local to each clone.

**`gdg wiki lint`**
Print a lint prompt. The checklist is the Lint section of `AGENTS.md`, keeping that logic out of the CLI. It is intended to run weekly from a home-server cron job.

Regenerate `cli/internal/wiki/openapigen/openapi.gen.go` after updating `wiki/openapi/openapi.yaml`.

### Regression tests to add

- **A push from a Japanese-only clone does not erase `content_en`** (partial-locale update).
- A sync upsert to an `origin: human` page is rejected with 4xx.
- An `origin: human` page is absent from snapshot `pages` and present in the sources manifest.
- Creating an agent page with an `origin: human` parent is rejected.
- Only pages with Japanese changes enter `TRANSLATION_QUEUE`; unchanged pages do not.
- `page.md` front matter contains `language`; do not generate `ja.md`/`en.md`.

### Manual E2E

1. `pnpm --filter @gdgjp/wiki dev`
2. `GDG_WIKI_URL=http://localhost:5177 gdg wiki clone --lang ja /tmp/wiki-test`
3. `cd /tmp/wiki-test && gdg wiki raw pull` — downloads `raw/**` and `AGENTS.md`.
4. `git status` is clean (`raw/` is ignored).
5. `gdg wiki ingest` — un-ingested documents appear in `INGEST_QUEUE.md`.
6. Process the first item with Claude Code → `git push` succeeds.
7. The Wiki app fills the affected page's English version after a few dozen seconds.
8. Removing `raw/` from `.gitignore` then running `git add raw/ && git push` is rejected with `only pages/** may be pushed`.
9. After `gdg wiki ingest --commit`, running `gdg wiki ingest` again reduces the queue.

# Stage 1 — Create the raw layer (`sources`)

## Context — Background and repository state

Separate primary information (`raw`) from Wiki pages and create a destination in `wiki/` where operations members can submit URLs.

The current Google Docs import turns each document tab into a 1:1 Wiki page, leaving 107 machine slugs such as `page-1786197821498` in the sidebar and damaging the UX. Isolate raw content in a separate table and UI so that Wiki pages contain only LLM-authored synthesized content.

This is the Raw layer of the three-layer LLM Wiki pattern (`llm-wiki.md`). The overall strategy is in `docs/plans/00-llm-wiki-overview.md`. Stages 2–5 build on this work.

**Dependencies:** None
**Workspace in scope:** `wiki/` only

### 2. R2 layout

```
raw/<sourceId>/<sourceDocumentId>/<contentHash>.md
raw/<sourceId>/assets/<objectId>-<contentHash>.<ext>
```

Use **content-addressed** keys for assets. Random IDs change paths in page bodies on every refetch, which changes `content_hash` every time and defeats “skip when hashes match.” Rewrite links in document bodies to the R2 key itself. Since the Stage 3 clone has `raw/**` at its root, R2 keys and clone file paths match, allowing local agents to open them directly.

On refetch, write a **new object with a different hash** and update `source_documents.r2_key`.
**Do not delete old objects.** This preserves raw immutability and makes it possible to diff what changed since the prior Ingest.

When the hash matches the existing content, skip both the R2 write and the `captured_at` update.

After every successful fetch, mark **paths not returned this time as `archived`**.
If a deleted or empty Doc tab retains its previous `ready` row, downstream Ingest continues reading content that the source already removed. Do not delete the row or R2 object; only change its status. Restore a returned path to `ready` (including along the same-hash skip path). Forgetting this would leave a restored tab permanently `archived` when its content has not changed.

Only update fetch completion when the source is **still `fetching`**. If a user archives a source during retrieval, completion must not silently restore it to `ready`.

**Guard every write with a fetch-attempt lease.** Cloudflare Queues deliver at least once, and a manual refresh
during a cron run produces a second job for the same source. Status alone cannot distinguish “my attempt” from
“someone else's attempt,” because both jobs set `status: fetching` and both then see `fetching` at completion.
The damaging case is not the duplicate fetch itself but the ordering: a slow older attempt finishing after a
newer one **archives the `source_documents` the newer attempt just discovered**, and overwrites `r2_key` /
`last_fetched_at` with staler values. The result is a source that looks `ready` while pointing at superseded
content — a failure with no error and no log line.

- Generate a fresh `attemptId` when claiming the source, and write it with the `status: fetching` transition.
- Every subsequent write in that job — `source_documents` upserts, the stale-path archival pass, and the final
  `ready` / `error` transition — is a compare-and-swap that additionally requires
  `fetch_attempt_id = <attemptId>`. A zero-row update means a newer attempt took over; **abandon the job with
  `ack()` and write nothing further.** Do not treat it as an error, and do not retry.
- Clear `fetch_attempt_id` on the terminal transition.
- Claiming is itself conditional: only claim when the source is not `archived`. Combined with the CAS, this keeps
  the existing archive-during-fetch rule intact.

This applies to the reconciliation pass specifically. Archiving “paths not returned this time” is correct only
relative to the attempt that produced the path list, so it must never run under a superseded lease.

> **Divergence from the shipped implementation.** As of `b54b338`,
> `wiki/workers/features/sources/fetch-source.ts` guards completion with `eq(sources.status, "fetching")` alone and
> has no `fetch_attempt_id`. Overlapping deliveries are therefore mutually indistinguishable. Adding the column
> needs its own migration (`00XX_add_source_fetch_attempt.sql`) rather than an edit to the shipped
> `00XX_add_sources.sql`.

### 3. API

Register routes in `wiki/app/routes.ts`. Protect all routes with `requireUser` and enforce `chapter_id` scoping.

- `POST /api/sources` — receive a URL, determine `kind`, register it as `pending`, and enqueue `SOURCE_FETCH_QUEUE`
- `GET /api/sources` — list sources (status, last fetched time, document count)
- `POST /api/sources/:id/refresh` — enqueue a refetch
- `POST /api/sources/:id/archive` — archive it (do not delete R2)

Reuse existing `isGoogleDriveUrl` / `isGoogleFormUrl` for `kind` detection.

**Use one registration implementation.** If the `/sources` form action and JSON API each implement insert + enqueue, chapter resolution splits into two places and one will inevitably rot. Centralize it in `createSource` in `app/lib/sources.server.ts`, and call it from both.

**Persist enqueue failure as `error`, on every path that enqueues.** Registration, `POST /api/sources/:id/refresh`,
and the cron sweep all set a row to `pending` and then call `SOURCE_FETCH_QUEUE.send`. If `send` throws or the
request dies between the two, the row stays `pending` with nothing scheduled to move it: no worker will ever pick
it up, no error is displayed, and the UI shows a source that is perpetually about to start. Wrap each enqueue so
failure writes `status: error` with an actionable `error_message`, and make refresh recoverable from that state.
Returning 202 to the client before confirming the enqueue is not acceptable here.

> **Divergence from the shipped implementation.** As of `b54b338`,
> `wiki/app/routes/api.sources.$id.refresh.ts` sets `pending`, then calls `send` unguarded and returns 202
> regardless. The registration path in `app/lib/sources.server.ts` should be checked against this rule as well.

**Make visibility a required registration input.** A source with null `chapter_id` can be read by every signed-in member, so do not design field omission to fall back to null. Distinguish an explicit “All” selection (`ALL_CHAPTERS`) from no selection (`chapter_required`, return 400). Raw content is unprocessed primary information, so do not default toward broad visibility.

### 4. UI

- Add a `/sources` route under the `routes/_app.tsx` layout.
- **Do not show it in the sidebar page tree.** Add one “Sources” entry to the `Sidebar.tsx` footer. Settings belongs in the Navbar user menu (`Navbar.tsx`), not the sidebar. **Do not add a Settings link.**
- Place a visibility select next to the URL input. It offers the member’s chapters (all chapters for administrators) plus “All,” and prevents submission with no selection.
- Screen elements: URL input, source-list table, per-row status badge / refetch / archive actions, and an expandable list of `source_documents`.
- Add i18n strings to `wiki/app/locales/{ja,en}/common.json` (default locale: `ja`).

**A free-text URL input is required, not optional.** The operating loop in
[00-llm-wiki-overview.md](00-llm-wiki-overview.md) starts with “paste a URL,” and `kind` covers `website` as well
as `google-doc`. A Google Picker can only return Drive items, so a Picker-only form makes the `website.ts` fetcher
unreachable from the product and leaves web-source ingestion API-only.

- The form accepts a typed or pasted URL, validated on submit. An unrecognized URL shows an inline error rather
  than being silently dropped.
- The Google Picker **may remain as a convenience** for choosing a Drive document, but it fills the same URL field
  rather than replacing it. The field must stay user-editable, not a hidden input bound to the picker selection.
- Submit is enabled whenever the URL field is non-empty and a visibility is chosen — it must not require a Picker
  selection.

> **Divergence from the shipped implementation.** As of `b54b338`, `wiki/app/routes/sources.tsx` renders `url` as a
> hidden input driven solely by the Picker, and disables submit unless a Drive document is selected. This section
> is not yet satisfied. Treat restoring the URL input as outstanding Stage 1 work, not as a new requirement.

### 6. Queue and cron

```toml

queue = "gdgjp-wiki-source-fetch"

[[queues.consumers]]
queue = "gdgjp-wiki-source-fetch"
max_batch_size = 1
max_batch_timeout = 30
```

Add a discriminator branch to the `queue` handler in `wiki/workers/app.ts`.
As required by existing convention, drop unrecognized messages with `ack()` (`wiki/CLAUDE.md`). Model the type guard after `isGoogleDocumentImportQueueBody` in `queue-processors.server.ts`.

Add a cron job to refetch sources whose `refresh_policy` is not `manual`.
Add a second entry to `[triggers].crons` and **also** update the `event.cron` discriminator in the `scheduled` handler.
The existing configuration has only `0 15 * * *` and does not distinguish crons, so this includes introducing that branch.

### 7. Exclude from search

Raw content is naturally excluded from Vectorize and full-text search because it does not enter `pages`.
To prevent regressions, add a test for `/search` and `wiki/app/features/ai-search/` ensuring that content originating from `sources` does not appear in results.

## Verification — completion criteria and validation

### Completion criteria

Pasting a Google Docs URL **or a plain web URL** into `/sources` finalizes Markdown in R2 and lists
`source_documents` with hashes. Nothing appears in the Wiki page tree.

### Commands

```bash
pnpm --filter @gdgjp/wiki migrate:local
pnpm --filter @gdgjp/wiki cf-typegen
pnpm --filter @gdgjp/wiki test
pnpm ci:quick
```

When changing bindings in `wrangler.toml`, **always run `cf-typegen`** (`worker-configuration.d.ts` is generated; do not edit it manually).

### Required unit-test coverage

- Refetching identical content does not write to R2 or change `content_hash`.
- The `(source_id, path)` UNIQUE constraint works.
- A message shape other than `SOURCE_FETCH_QUEUE` is `ack()`ed by the `queue` handler.
- An unrecognized URL returns 4xx from `POST /api/sources`.
- Registering without visibility returns 400, creates no row, and enqueues nothing.
- Specifying a chapter the user does not belong to returns 403.
- If enqueueing fails, the row becomes `error` rather than remaining `pending` indefinitely — assert this
  separately for registration, for `POST /api/sources/:id/refresh`, and for the cron sweep.
- A source archived during retrieval is not restored to `ready` by completion (for both success and failure).
- A `path` returned previously but absent this time becomes `archived`; if restored, it returns to `ready`.

Duplicate-delivery tests for the attempt lease. These are the ones that fail silently in production, so drive the
two jobs explicitly rather than relying on timing:

- Delivering the same queue message twice does not produce duplicate `source_documents` rows.
- **Reverse completion order:** attempt A claims, attempt B claims (superseding A), B completes, then A completes.
  A's completion writes nothing — `r2_key`, `last_fetched_at`, `content_hash`, and every `source_documents.status`
  still reflect B.
- Under the same reverse ordering where B discovers a **new** `path` absent from A's result, A's reconciliation
  pass does not archive it.
- An attempt whose CAS matches zero rows is `ack()`ed and does not consume retry budget or set `error`.
- `fetch_attempt_id` is null after a terminal `ready` or `error` transition.
- Fetch failures that **cannot be fixed by retrying** (Drive not linked, 404/403, unsupported URL) are `ack()`ed without consuming retry budget. 429 and 5xx are retried.

### Manual E2E

1. Run `pnpm --filter @gdgjp/wiki dev` (`:5177`).
2. Sign in as a user with Google Drive linked and open `/sources`.
3. **Type** a Google Docs URL into the field → status transitions `pending` → `fetching` → `ready`.
4. Inspect D1 in `.wrangler/state` and confirm `source_documents` has one row per tab plus `content_hash`.
5. Refetch the same URL and verify that `content_hash` does not change and no new R2 object appears (when the hash matches, `captured_at` does not update either).
6. **Paste a plain web URL** (not a Drive item) and confirm it registers as `kind: website` and reaches `ready`
   through `website.ts`. This is the path a Picker-only form cannot reach.
7. Submit a malformed URL and confirm an inline error, with no row created.
8. **Confirm that no new page appears in the sidebar.**

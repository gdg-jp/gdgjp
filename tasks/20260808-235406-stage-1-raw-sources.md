# Stage 1 — Introduce the Raw Layer (`sources`)

> Generated from Claude Code plan: `/Users/hari/proj/gdgjp/docs/plans/01-sources-raw-layer.md`
> Overall approach: `docs/plans/00-llm-wiki-overview.md`

## Goal

Separate primary information (raw) from Wiki pages and create a receiving area in `wiki/` where operations members can submit URLs.

The current Google Docs import turns Doc tabs into Wiki pages one-to-one, so 107 machine slugs such as `page-1786197821498` appear in the sidebar and damage the UX.
Isolate raw in a separate table and UI, and make Wiki pages contain only LLM-authored compositions.

This is the Raw layer of the three-layer LLM Wiki pattern (`llm-wiki.md`). Stages 2–5 build on it.

## Acceptance criteria

### 1. Data model

Add three tables to `wiki/app/db/schema.ts` and `wiki/migrations/00XX_add_sources.sql`.
Write migrations as **handwritten SQL** (do not use Drizzle generation). `migrate:local` regenerates `schema.sql`, so do not edit it manually.

### 2. R2 layout

```
raw/<sourceId>/<sourceDocumentId>/<contentHash>.md
raw/<sourceId>/assets/<assetId>-<fileName>
```

On retrieval, write a **new object with a different hash** and replace `source_documents.r2_key`.
**Do not delete the old object.** This guarantees raw immutability and enables a diff showing what changed since the previous Ingest.

If the hash matches the existing one, skip both the R2 write and `captured_at` update.

### 3. API

Register routes in `wiki/app/routes.ts`. Protect all routes with `requireUser` and enforce `chapter_id` scoping.

- `POST /api/sources` — accept a URL, detect `kind`, register it as `pending`, and enqueue it on `SOURCE_FETCH_QUEUE`
- `GET /api/sources` — list sources (status, last retrieval date, document count)
- `POST /api/sources/:id/refresh` — enqueue a refresh
- `POST /api/sources/:id/archive` — archive it (do not delete R2)

Reuse the existing `isGoogleDriveUrl` / `isGoogleFormUrl` to detect `kind`.

### 4. UI

- Create a `/sources` route under the `routes/_app.tsx` layout.
- **Do not show it in the sidebar page tree.** Add a “Sources” item immediately above “Settings” in the `_app.tsx` sidebar footer.
- Screen elements: URL input, source-list table, status badge / refresh / archive controls per row, and an expandable list of `source_documents`.
- Add i18n strings to `wiki/app/locales/{ja,en}/common.json` (default: `ja`).

### 5. Retrieval worker

Create `wiki/workers/features/sources/`.

- `fetch-source.ts` — dispatcher. Select a fetcher by `kind` and persist results to `source_documents` + R2.
- `google-doc.ts` — reuse `tools/google-drive.ts` and `tools/google-docs/workspace.ts`. One tab = one `source_document`, and `path` joins the tab hierarchy with slashes. **Only change the destination from pages to `source_documents` + R2.**
- `website.ts` — reuse `tools/web-fetch.ts` and the `BROWSER` binding.
- `persist.ts` — consolidate hash calculation, R2 writes, and `source_documents` upserts.

Follow the existing layer convention that internal implementations in `workers/features/ingestion/` must not be imported directly from UI routes
(`wiki/workers/features/ingestion/README.md`).

### 6. Queue and cron

Add the following to `wiki/wrangler.toml` in the same form as the existing `GOOGLE_DOCUMENT_IMPORT_QUEUE`.

```toml
[[queues.producers]]
binding = "SOURCE_FETCH_QUEUE"
queue = "gdgjp-wiki-source-fetch"

[[queues.consumers]]
queue = "gdgjp-wiki-source-fetch"
max_batch_size = 1
max_batch_timeout = 30
```

Add a discrimination branch to the `queue` handler in `wiki/workers/app.ts`.
As required by existing conventions, discard unrecognized messages with `ack()` (`wiki/CLAUDE.md`).
Follow `isGoogleDocumentImportQueueBody` in `queue-processors.server.ts` for the type guard.

Add a cron job to periodically retrieve sources whose `refresh_policy` is not `manual`.
Add a second entry to `[triggers].crons` and **at the same time** update the `event.cron` discriminator in the `scheduled` handler.
The current configuration has only `0 15 * * *` and does not discriminate crons, so include that discrimination branch.

### 7. Exclude from search

Because raw does not enter `pages`, it is naturally excluded from Vectorize and full-text search.
To prevent regressions, add a case to tests for `/search` and `wiki/app/features/ai-search/` asserting that content originating from `sources` does not appear in results.

## How to verify

```bash
pnpm --filter @gdgjp/wiki migrate:local
pnpm --filter @gdgjp/wiki cf-typegen
pnpm --filter @gdgjp/wiki test
pnpm ci:quick
```

After changing bindings in `wrangler.toml`, **always run `cf-typegen`** (`worker-configuration.d.ts` is generated, so do not edit it manually).

Establish these unit tests:

- When retrieving the same content again, it is not written to R2 and `content_hash` does not change.
- The UNIQUE constraint on `(source_id, path)` works.
- Message shapes other than `SOURCE_FETCH_QUEUE` are `ack()`ed by the `queue` handler.
- An unrecognized URL receives 4xx from `POST /api/sources`.

Manual E2E:

1. Run `pnpm --filter @gdgjp/wiki dev` (`:5177`).
2. Sign in with a user that has Google Drive linked and open `/sources`.
3. Register a Google Docs URL → status transitions from `pending` → `fetching` → `ready`.
4. Inspect the D1 database in `.wrangler/state` and confirm `source_documents` has one row per tab and a `content_hash`.
5. Retrieve the same URL again and confirm `content_hash` remains unchanged while only `captured_at` updates.
6. **Confirm that no new page appears in the sidebar.**
